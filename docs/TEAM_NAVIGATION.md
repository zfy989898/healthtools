## 第一层：北极星（North Star）

### 核心北极星指标

**月自然流量 → 月收入 → 可索引页数**

三条北极星线，按优先级排序：

| 优先级 | 北极星指标 | 当前值 | Day 30 目标 | 说明 |
|--------|-----------|--------|-------------|------|
| P0 | 可索引页数 (`page_count`) | 14 | ≥ 20 | 新站沙盒期3-6月，真正对标是「可被Google收录的页面数」 |
| P1 | GA4 注入状态 (`ga4_injected`) | false | true | 数据追踪是后续所有优化的前提 |
| P2 | AdSense 上线状态 (`adsense_pub`) | 已挂待批 | 获批 | 变现路径已开通，等待审核 |

**北极星原则：**
- 每日只看 `verify-latest.json` 的 `page_count`、`all_200`、`ga4_injected`、`adsense_pub` 四个字段
- 数字上涨 = 做对了；数字未变 = 当天无产出
- 任何 md 清单 / 评分卡 / 改进指令 ≠ 北极星，不视为交付

┌─────────────┐                  ┌─────────────┐                  ┌─────────────┐

### 阶段里程碑对照表

| 里程碑 | 时间窗口 | 关键交付物 | 验收判据 |
|--------|----------|-----------|----------|
| M1: GA4 接入 | Day 1–2 | GA4 Measurement ID 注入全部页面 | `ga4_injected: true` |
| M2: 可索引页扩充 | Day 1–7 | 新增至少6页（工具页或支撑页） | `page_count ≥ 20` |
| M3: 全量达标 | Day 1–14 | 所有页面返回200 + 新增至35页 | `all_200: true` + `page_count ≥ 35` |
| M4: AdSense 重提 | Day 21 | 重新提交 AdSense 申请 | `adsense_pub` 状态更新 + 申请记录 |
| M5: 规模上线 | Day 30 | 站点规模初步成型 | `page_count ≥ 50` |
| M6: 流量起飞 | Day 90 | 自然流量稳定 | `GSC 周点击 > 100` |

## 看板列结构（Kanban Board Layout）

```
┌──────────┬──────────┬──────────┬──────────┐
│  Backlog │  Today   │ Blocked  │   Done   │
│          │          │          │          │
│ • 候选   │ • 当前   │ • 阻塞   │ • 已完成 │
│   选题   │   执行   │   任务   │   任务   │
│          │          │          │          │
│ • 待选   │ • 进行中 │ • 原因   │          │
│   新工具 │          │   说明   │          │
│          │          │          │          │
└──────────┴──────────┴──────────┴──────────┘
```

### 列操作规范

| 列 | 操作规则 |
|----|----------|
| Backlog | 所有待执行任务入库，不限制数量 |
| Today | 每角色同时只有一张卡，避免多任务切换 |
| Blocked | 必须标注原因和已尝试清单，阻塞超 24h 才可上报 |
| Done | 完成卡归档，自动保留完成时间和结果字段 |

## 执行纪律

1. **晨会前**：先读 `verify-latest.json`，确定今日增量 N
2. **执行中**：写页 → 构建 → 部署 → 自验 200 → 更新 sitemap
3. **晚间**：hermes 跑 `ops_verify.py`，数字入日志
4. **无达标即无有效日**：数字未变 = 次日补产
